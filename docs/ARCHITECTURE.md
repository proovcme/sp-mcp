# Архитектура

```text
MCP / CLI / JSON API
          │
        Service ─── optional Uvyazka MCP bridge
          │                  │
   source discovery     versioned unapproved project analysis
          │
       Network ── robots policy, host allowlist, TLS, rate/size/time bounds
          │
       Parsers ── identity, literal blocks, dates, revision links, HTML cells
          │
        Store ─── content-addressed originals + immutable extraction snapshots + FTS5
          │
     Verification ── dated observations, amendments, unresolved conditions, conflicts
```

`verification.py` не выполняет сеть и не знает о MCP. `storage.py` не принимает юридических решений.
`uvyazka.py` работает через инструменты целевой системы, а не через её внутренние таблицы.
Зависимостей от API моделей и облачного хранилища нет.

## Идентичность и версии

Нормализованное обозначение не объединяет разные годы стандартов в одну сущность.
Карточка изменения имеет номер изменения отдельно от базового обозначения; статус изменения не
используется как статус основного документа. Редакции и сторонние копии сохраняют собственные URL.

Идентификатор снимка зависит от URL, SHA-256 исходных байтов и SHA-256 извлечения.
Новый парсер может создать новый снимок из прежнего оригинала без перезаписи истории.
Каждое чтение проверяет оригинал и извлечение. Повторный сетевой запрос добавляет наблюдение времени;
дата проверки отделена от даты редакции, утверждения и введения.

Отчёт проверки неизменяем и имеет `verification_id`, зависящий от его содержимого.
Он содержит собственные источники и снимок загруженного текста, если тот был передан.

## Расширение источников

Для нового источника нужны: явная роль и область покрытия, политика доступа, обнаружение документов,
устойчивая идентификация, парсер буквальных полей, исходные байты с контрольной суммой и регрессии.
Нельзя повышать вторичную справку до официального подтверждения или угадывать дату публикации.

В 0.1 официальная проверка реализована только для ГОСТ/СП через каталог Российского института
стандартизации; МегаНорм — вторичный источник текстов. Прочие адаптеры не декларируются реализованными.
При добавлении новых источников результат должен сохранять независимые наблюдения и показывать конфликты.

## Следующие этапы

1. Независимые официальные адаптеры и подтверждение исторических интервалов по актам.
2. Возобновляемое индексирование выбранных тематических подборок и мониторинг изменений.
3. Расширение версионируемого инженерного словаря и оценка качества ранжирования.
4. Сопоставление редакций на уровне изменённых пунктов.

## Поиск и веб-клиент 0.2

`web.py` обслуживает статический интерфейс и JSON API поверх того же `Service`.
Пакет не требует Node.js для запуска; HTML/CSS/JS входят в wheel. Веб-оболочка не запускает MCP-клиента
или LLM для поиска: это прямые вызовы ядра. Данные источников выводятся как текст, исходный HTML не исполняется.

`linguistics.py` нормализует русские словоформы Snowball и задаёт связанные понятия. `retrieval.py`
строит адресные фрагменты с исходными смещениями и индекс FTS5, выполняет BM25 и понятийное расширение.
Поддерживаются близкие написания. Словарь задаёт ассоциации для поиска, а не нормативную эквивалентность.
Основные режимы `concept` и `lexical` не загружают модель. Кодовое обозначение сохраняет отдельный точный маршрут.

Понятийное обнаружение использует ограниченные дополнительные запросы к каталогам и контекстные условия
для заголовков; оно не задаёт заранее номера документов. Доступные ссылки текста сопоставляются
с найденным обозначением. Предварительная загрузка ограничена двумя разными документами и тремя попытками.

`validity.py` строит фильтр из свежих явных статусов: результат проверки на текущую дату, официальная карточка,
официальная подпись каталога, затем вторичная карточка или однозначное примечание об отмене документа.
Изменение не определяет статус базового документа; историческая проверка не определяет сегодняшний статус.
Будущая или частичная отмена в примечании не скрывает весь документ. При конфликте источников одинакового
приоритета документ остаётся видимым. Непроверенный статус не повышается до действующего.
Фильтр применяется по обозначению до пагинации к названиям, фрагментам и библиотеке. История и чтение
снимка по идентификатору сохраняются; `include_inactive=true` возвращает скрытые документы.

Режимы `semantic`/`hybrid` дополнительно используют явно настроенный локальный JSON-lines worker.
Пространство векторов включает сведения о модели и фактические SHA-256 весов. Индексирование идёт
порциями в фоне с сохранением готовых векторов и продолжением после перезапуска. Неподготовленность
или ошибка дополнительного индекса возвращается явно. Готовность индекса не означает полноту нормативного корпуса.

Сеансовый токен и Origin защищают запись нормативных связей. При Bearer-аутентификации HTML-оболочка
может открыться без токена, но ни один API с данными не становится публичным. Токен в GUI хранится
только в памяти текущей вкладки. Прокси «Увязки» использует её штатную защиту записи и сохраняет анализ
своим ядром, сохраняя независимые происхождения проектного и нормативного документов.
