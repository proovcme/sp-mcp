# Интеграция с «Увязкой»

## Веб-интерфейс

В актуальной «Увязке» есть раздел «Поиск норм». Запустите `sp-mcp web`: встроенный интерфейс
получает тексты, редакции и результаты из той же базы SP MCP. Нормативный корпус в проект не копируется.
По умолчанию поиск работает без модели: словоформы, BM25 и инженерный словарь.

В этом режиме проект и исходник выбираются непосредственно из реестра «Увязки»; ручной ввод SHA-256
не нужен. Сохранение выполняется её штатным приложением с проверкой исходника и ревизии анализа.
Прокси по умолчанию использует `http://127.0.0.1:8767`; на стороне «Увязки» адрес можно изменить
через `UVYAZKA_SP_URL`, токен сервиса — через `UVYAZKA_SP_TOKEN`. Разрешён только loopback.

Самостоятельный веб-интерфейс доступен на `http://127.0.0.1:8767/`. Его вкладка «Увязка» использует
настроенный ниже MCP-мост; встроенная панель работает с собственным реестром проекта.

Интеграция идёт через публичный MCP-инструмент `save_structure_analysis`, без прямой записи в SQLite.
Сохраняется версия **неутверждённого анализа**, связанная с исходным документом проекта.

## Две независимые стороны доказательства

- Документ проекта: `project_id`, зарегистрированный `doc_id`, SHA-256, необязательная физическая страница PDF.
- Нормативный источник: обозначение, редакция, `snapshot_id`, SHA-256 оригинала и извлечения, пункт,
  `verification_id`, дата проверки, официальные карточки, конфликты и ограничения.

Нормативный URL нельзя подставлять вместо зарегистрированного источника проекта.
Шифр документа не доказывает его применимость к объекту. `accepted=false`, `applicability=not_assessed`.

## Работа без прямого подключения

1. В «Увязке» выбрать проект и прочитать исходный документ со ссылкой на норматив.
2. В `sp-mcp` открыть нормативный документ, прочитать пункт, вызвать `sp_check_status` с его `snapshot_id`.
3. Вызвать `sp_prepare_uvyazka_link`:

```json
{
  "project_id": "synthetic-project",
  "project_source": {
    "doc_id": "EXACT_ID_FROM_UVYAZKA",
    "sha256": "EXACT_SHA256_FROM_UVYAZKA"
  },
  "snapshot_id": "EXACT_SNAPSHOT_FROM_SP",
  "verification_id": "EXACT_VERIFICATION_FROM_SP",
  "clause": "7.1.1"
}
```

Это пример формы запроса, а не готовые значения. Результат содержит имя инструмента и его точные аргументы.
Ассистент может передать их в подключённый `uvyazka.save_structure_analysis`.

## Прямое подключение

Настроить в окружении процесса `sp-mcp`:

```text
SP_MCP_UVYAZKA_COMMAND=/absolute/path/to/uvyazka/python
SP_MCP_UVYAZKA_ARGS=["-X","utf8","-m","uvyazka.server"]
SP_MCP_UVYAZKA_HOME=/absolute/path/to/existing/uvyazka-state
```

На Windows `COMMAND` — Python из окружения установленной «Увязки», например `…/.venv/Scripts/python.exe`.
Аргументы передаются списком без shell. Каталог состояния должен совпадать с используемым панелью «Увязки».
Без этих настроек прямой мост возвращает `UVYAZKA_NOT_CONFIGURED`; подготовка пакета остаётся доступной.

`sp_uvyazka_projects` читает реестр проектов. `sp_attach_uvyazka_link` подготавливает пакет и отправляет его
через настроенное подключение. Скрытого выбора проекта и автоматического импорта исходных папок нет.

## История и повторные проверки

Идентификатор анализа стабилен для проекта, исходного документа, обозначения норматива и пункта.
Повтор идентичного запроса идемпотентен. Для изменения передаются предыдущая `expected_revision`
и содержательная `reason`; «Увязка» самостоятельно проверяет ревизию и фактический хеш исходника.

Если исходник проекта изменился, штатная проверка зависимостей «Увязки» помечает связь устаревшей.
Если изменился норматив, нужна новая проверка `sp_check_status` и новая версия анализа. Автоматического
фонового мониторинга в 0.1 нет. Дата проверки и сохранённые ссылки позволяют увидеть возраст результата.

Никакие инженерные факты, требования, геометрия или результаты проверки соответствия автоматически
не утверждаются. Связь сохраняет основание для последующего рассмотрения.

## Проверка совместимости

Опциональный тест `tests/test_uvyazka_acceptance.py` запускает установленную «Увязку» на временном
синтетическом проекте: сохраняет ссылку, проверяет идемпотентность и устаревание после изменения исходника.
Тест не использует рабочую базу пользователя и реальные проектные документы.
